# Get Design Context

Run this before product-design build or exploration work. Determine only what is necessary:

1. What product, feature, screen, workflow, or component is being designed?
2. What outcome should it help the user achieve?
3. Is the intended surface web, desktop web app, or mobile app, if the source does not make this clear?

Do not ask again for facts already provided. If a material answer is missing, ask one focused question. Once the target and outcome are clear, briefly restate the brief, name any assumptions, and continue to the relevant workflow without asking for redundant approval.

Do not write UI, create files, scaffold a prototype, or start a server until the target and outcome are known. A complete written brief is sufficient for ideation; a visual target is required for `$image-to-code`.
