# UX Research

Start by restating the product, audience, time horizon, and scope. Use current, credible sources and cite each important claim. Public sources may include product documentation, issue trackers, forums, reviews, developer communities, and social discussion; use internal sources only when available and authorized.

Cluster evidence rather than dumping comments. Separate workflow/UI friction, onboarding, documentation, account or billing, developer experience, reliability, and feature requests. Rank findings by severity, frequency signal, confidence, and leverage.

Return a concise brief containing:

- an executive read;
- ranked problems with the user goal, affected surface, evidence, confidence, and recommended product move;
- a source map, including weak or missing evidence; and
- an opportunity map for near-term fixes, longer-term work, and further research.

Clearly distinguish observed evidence from inference and avoid treating anecdotes as prevalence data.
