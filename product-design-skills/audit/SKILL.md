# Product Experience Audit

Use this for review, critique, assessment, or feedback on an existing user experience. Establish the surface, the user task, and a capture method before drawing conclusions. Capture the actual flow in the current run; do not base findings on memory or indirect research.

For each important step, wait for a stable screen, capture it, inspect the saved image, note visible behavior, and record strengths, risks, and limits. Treat loading screens, login walls, errors, blocked states, and incomplete screenshots as evidence gaps—not as proof of the experience.

Default to an inline report with screenshots in order. Include an overall verdict, a numbered step list, high-impact fixes, and explicit evidence limits. Tie every finding to a screen or step. State accessibility risks visible from the flow, while making clear that screenshots alone cannot prove conformance.

When a canvas walkthrough is requested, place each verified screenshot next to its step and notes in sequence, then inspect the completed canvas before handoff.
